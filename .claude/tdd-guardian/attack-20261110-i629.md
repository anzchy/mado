# Specification Attack — tests-20261110-i629.md

## Round 1: GAPS FOUND (1)

RC positive cases covered only shortVersion `0.0.1`. An implementation allowing exact final URLs for all versions but RC URLs only for `0.0.1` would pass every case and fail the next version's release candidate.

Missing case: S6 consistent version renaming from `0.0.1` to `1.2.3` with tag `mado-v1.2.3-rc.4` and asset `Mado-1.2.3.dmg`, followed by rejection when only the tag changes to `mado-v1.2.4-rc.4`.

## Round 2: SURVIVED

Designer added the named S6 version-renaming case and real-generator coverage for both versions. Read-only reassessment found no surviving plausible attack within the plan's scope.

| Attack | Killed by |
|--------|-----------|
| Constant true/false | Positive and malformed URL cases |
| First-release-only RC special case | Consistent version renaming |
| Checking only one feed item | Mixed-feed permutation and rejection propagation |
| Arbitrary prerelease acceptance | Malformed RC suffix boundaries |
| Loose URL matching | Scheme, host, repository, query, fragment and extra-path cases |
| Numeric RC overflow | Long positive RC suffix |
| Ignoring tag/asset version correspondence | Mismatched URLs and version-renaming mutation |
| Duplicate upsert | Real-generator idempotence |
| Dropping historical entries | Retained-item text and version assertions |

Both units have stated laws covered by S5/S6. No asynchronous, external-network or shared-state behavior is claimed. Publication, Sparkle channel policy and full XML validation remain explicitly outside scope.

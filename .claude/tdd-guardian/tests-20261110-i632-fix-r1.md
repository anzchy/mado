## Unit: WI-1 external-interrupt ownership and cleanup

**Law**: A heavy-lock follower cannot be admitted while any verified Swift process owned by the interrupted watchdog remains alive. Interrupt cleanup is idempotent, bounded by parent grace, and never kills an unrelated process.

### Case: Auditor TERM reproducer proves death before follower admission
- **Category**: failure
- **Lane**: integration
- **Spec level**: S5 — process/lock ownership across interruption and admission.
- **Input**: Actual heavy-lock with isolated test locks runs real watchdog and external fake Swift leader plus detached helper. Both install TERM-resistant handlers and readiness/PID markers before test sends TERM to heavy-lock. Queue actual follower before signalling; follower checks both PIDs at admission and records their liveness. Safety exits are longer than the relevant interrupt assertion window.
- **Expected output**: Current implementation yields specific RED: follower observes live owned work. GREEN follower observes both dead at its admission, parent has failed from external signal, no retry occurred. Signal-to-follower admission is strictly<8 seconds (target about4; parent grace10). A normal assertion failure rather than harness timeout is required for goal RED.
- **Observable side effect**: Admission-time PID record, retained command/watchdog logs and final absence of leaked processes.
- **Assertion strategy**: Level3 — real OS signals/locks and follower-side liveness checks. Capture evidence before test finally kills/reaps any leaked leader/helper; register unconditional cleanup immediately after spawning.
- **Mock boundary**: External Swift command only, for long controlled work; real repository launcher/watchdog/lock code.
- **Paired integration test**: This is the actual launcher/watchdog/lock system path with a controlled external workload; existing real Swift split validation covers executable compatibility separately.
- **Refactor that would break this**: Releasing lock before owned-process death or swallowing interruption; private helper names do not matter.

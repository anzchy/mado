## Unit: ViewerSession next/previous over PreviewSet

**Law**: Navigation preserves the frozen membership and order. With looping on and at least two members, one full cycle in either direction returns to its starting item; next followed by previous is a round trip. Without looping, endpoints are stable.

### Case: Preview live toggle at both boundaries
- **Category**: state
- **Lane**: unit (`swift-red`, then package `unit`)
- **Spec level**: S5 — observable sequence through off/on/off transitions.
- **Input**: Real in-memory preferences store; Grid order [A, B, C], initially current A. Space; previous while off; toggle on; previous; next; toggle off; previous; next twice; next; toggle on; next.
- **Expected output**: Current sequence A, C, A, A, B, C, C, A. Preference remains on after Esc/reopening a preview.
- **Observable side effect**: The host's presentation receives only actual new image targets; no wrap cue is introduced.
- **Assertion strategy**: Level 4 — assert session currentItemID after every command and persisted store value after return/reopen; presentation target sequence supplements state.
- **Mock boundary**: Native presentation host is a recording boundary; preference and session are real.
- **Paired integration test**: `issue345GridSpaceMenuWrapEscapeReturnsVisibleCurrentItem` below exercises real CanvasWindowController, menu, Grid and ImageIO pipeline.
- **Refactor that would break this**: Reading a cached preference only at preview entry, ignoring reverse wrap, or always wrapping would break state assertions; renaming stepping internals would not.

### Case: Grid sort/filter cycles and selection confinement
- **Category**: property
- **Lane**: unit (`swift-red`, then package `unit`)
- **Spec level**: S5 — finite cycle/round-trip/membership invariants across transitions.
- **Input**: Counts 2, 3, 5; ascending and descending folder conditions with PNG filter excluding a JPG, using the real folder fixture/projection order. Open a Preview Set at the first member. Run two full next cycles, then two full previous cycles. Repeat using a noncontiguous multi-selection, opened at its last selected member.
- **Expected output**: Every step equals the independent modular-index oracle over the actual filtered/sorted order (or its selected subset); each full cycle returns to the start; membership/order never grow or reorder. JPG and unselected images never appear, including both wrap directions.
- **Observable side effect**: Only members of the frozen order are presented.
- **Assertion strategy**: Level 4 — assert currentItemID, frozen itemIDs, selected-set conservation and each cycle's starting item; exact host target sequence supplements state.
- **Mock boundary**: Folder scanner fixture supplies controlled input events; presentation boundary records targets. Production sorting, filtering, selection, PreviewSet and session remain real.
- **Paired integration test**: `issue345GridSpaceMenuWrapEscapeReturnsVisibleCurrentItem` uses real filesystem scan and real presentation. Existing folder adapter integration tests cover source acquisition; no new adapter behavior is introduced.
- **Refactor that would break this**: Wrapping over the complete folder rather than the frozen selection, independently re-sorting IDs, or adding newly arriving items would violate the oracle/invariant.

### Case: Empty and singleton never reopen
- **Category**: guard
- **Lane**: unit (`swift-red`, then package `unit`)
- **Spec level**: S5 — repeated boundary commands are idempotent.
- **Input**: Empty Grid; singleton Preview Set [A]; singleton Finder set [a.png]. Loop false and true; repeated next/previous commands.
- **Expected output**: Empty Grid cannot open a preview; empty set has no target; singleton current stays A/a.png and receives no replacement presentation/load. Singleton arrows cannot cause self-reload.
- **Observable side effect**: No extra image open or presentation is generated after the initial display.
- **Assertion strategy**: Level 4 — unchanged current state and empty/no-preview state; Level 2 — no additional presentation or input open beyond the captured initial sequence.
- **Mock boundary**: Recording native presentation/input host boundary only.
- **Paired integration test**: `issue345GridSpaceMenuWrapEscapeReturnsVisibleCurrentItem` exercises real presentation; singleton session test checks the stop decision before native loading.
- **Refactor that would break this**: Modulo-one self-wrap, force-reloading unchanged targets, or treating empty membership as navigable would fail.

## Unit: ViewerSession next/previous over FilePreviewSet

**Law**: Next/previous preserve the frozen input list; cycles return to the same file and never introduce a file outside the list. Loop-off endpoints are stable.

- **Lane**: unit (`swift-red`, then package `unit`)

## Unit: ViewerSession image presentation after navigation wraps

**Law**: The last navigation intent owns presentation; a stale decode completion cannot replace a newer target.

### Case: Fast paging across wrap rejects stale decode
- **Category**: failure
- **Lane**: unit (`swift-red`, then package `unit`)
- **Spec level**: S5 — latest-intent invariant under out-of-order asynchronous completions (named VIEW-09 failure mode).
- **Input**: Three member Preview/Finder variants with loop on, current last C. Route next to A, then next to B without waiting for A's decode. Use existing controlled generation pipeline boundary; settle B first, then A (and any pending C). Use real ViewerImageLoader/session generation handling.
- **Expected output**: Navigation current and imageLoader.presented identify B. Settling older A/C cannot change presented B, and settled phase remains correct. No assertion relies solely on a callback being invoked.
- **Observable side effect**: Actual decoded-image presentation state remains B after all pending completions drain.
- **Assertion strategy**: Level 4 — assert presented file/name/render key and current target after each release; Level 2 image host's shown target is a supplement.
- **Mock boundary**: Decode timing and access-lease acquisition use existing image-pipeline fixture boundaries to schedule completion; production session and loader remain real.

- **Refactor that would break this**: Opening through a path that skips generation invalidation or allowing cancelled decodes to publish would replace B with an old file.

## Unit: ViewerSession Esc restoration and CanvasWindowController returnToGrid

**Law**: Original selection/anchor are conserved across preview; once navigation has wrapped, the latest viewed member becomes Grid Current Item on Esc and is visible. With no wrap, the established origin-restoration contract remains unchanged.

### Case: Wrap history survives later paging and toggling off
- **Category**: state
- **Lane**: unit (`swift-red`, then package `unit`)
- **Spec level**: S5 — return invariant across wrap, ordinary paging, preference transition and Esc.
- **Input**: Original current last member; original selected subset and scroll anchor retained. Next wraps first, next lands second, toggle off, Esc. Also reverse-wrap first→last, more than one wrap, and a fresh preview that performs no wrap.
- **Expected output**: After wrap history, browsing current is latest viewed member; original selectedItemIDs/anchor remain. The scroll target requests that member. Disabling loop after wrapping does not erase return destination. Fresh/no-wrap preview restores original current, selection, anchor and scroll contract.
- **Observable side effect**: Returned Grid's target differs from original only for the wrap path; future previews start from the resulting Current Item.
- **Assertion strategy**: Level 4 — mode, current item, selected set, anchor and scroll target after Esc.
- **Mock boundary**: Recording native host boundary; no private stepping API is driven.
- **Paired integration test**: `issue345GridSpaceMenuWrapEscapeReturnsVisibleCurrentItem` verifies the real viewport.
- **Refactor that would break this**: Using the opening current, only recording wrap destination once, making restoration depend on the preference's final value, or accidentally retaining wrap history into a fresh preview would fail.

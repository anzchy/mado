## Decisions the implementer must confirm (found while designing)

1. **The WI-1 unsaved law conflicts with a counter.**
   - Take this sequence: `add A`, `markSaved`, `undo`, `add B`. An NSDocument-style counter that goes up and down ends back on the saved revision and reports *saved*, even though the marks differ.
   - The matrix requires **unsaved** here. So `revision` must be a fresh history-node id (go to a new node on each add; on undo/redo, return to the earlier node), not a value that goes up and down.
   - Same for `add A`, `save`, `undo`, `add A` (an identical mark): the matrix requires **unsaved**, because once redo is cleared the saved node can never be reached again.
   - So the plan's literal law `hasUnsavedMarks == (marks != marksAtLastSave)` is only checked over generated **distinct** marks. Case `docUnsavedTracksSavedHistoryNodeOverSeededOps` uses the history-node oracle.
2. **⌘E on `.detailLimited`:** allowed. The image is on screen, so this matrix counts it as "shown".
3. **errno with no mapping** (for example `EIO`): the matrix expects `.permissionDenied`. Change `writerMapsErrno` if you choose otherwise.
4. **Two seams are needed (failure injection at the file-system boundary, not a mock of our own code):**
   - an `AnnotatedCopyWriter` step hook (`WriteStep` with cases `leaseAcquire, tempCreate, encode, identityCheck, move, release`), so one test can make a single step fail or make a file appear;
   - an injected `writableTypes: Set<UTType>` on `AnnotatedCopyPlan`.
   
   The real list is covered by `writableTypesFromImageIO`.

## Amendment, spec-adversary round 1 (2026-11-13): 6 gaps plus 1 matrix defect closed

The implementer applied the adversary's named missing cases directly, one for each gap. These supersede the rows above where they conflict.

1. **Gap 1: close and quit must be able to proceed.**
   - Add `annotateLeaveOutcomeForEveryReason` (unit, S5). It is a law over every reason in {escape, closeWindow, quitApp, changeImage} and every resolution:
     - `.discard` gives `.proceed` and `annotateMode == nil`;
     - `.save`, then `.saved(u)`, gives `.proceed`;
     - `.save`, then `.failed(x)` or `.panelCancelled`, gives `.refused`, and the mode and marks are kept.
   - Add `issue690CloseDiscardCloses` and `issue690QuitDiscardReplies` (e2e). When the alert hook answers Discard, `windowShouldClose` returns true and the quit replies true.
2. **Gap 2: real image changes must ask.**
   - Decision: while annotating, `isEnabled(.open) == false`, so the ⌘O menu item is disabled. An external open (Finder or drop, through `openInput`) goes through `requestLeave(.changeImage)`.
   - Add `annotateOpenDisabledWhileActive` (unit, S3): `isEnabled(.open)` is false while active and true after exit, and the router refuses `.open`.
   - Add `issue690ExternalOpenAsksAndCancelKeeps` (e2e): `openInput([other])` with unsaved marks raises the prompt; Cancel leaves the image URL, the marks and the mode unchanged.
3. **Gap 3: the save completion marks the revision captured when the save started.**
   - Add `annotateEditDuringSaveStaysUnsaved` (unit, S3):
     - add mk1, ⌘S begins (capturing the revision), add mk2, then `.saved(u)`: `hasUnsavedMarks == true` and Esc raises the prompt;
     - the same with `undo` in place of add mk2.
4. **Gap 4: only permission errors fall back to the panel.**
   - In `writerMapsErrno`, EIO now maps to `.writeFailed`.
   - `.writeFailed` joins the typed set that the at-any-step law accepts.
   - Add `annotateOnlyPermissionErrorsReplanToPanel` (unit, S2): after `.failed(e)` for e in {sourceMissing, accessLost, diskFull, writeFailed, encodeFailed, folderMissing, nameExhausted}, the next plan is still `.direct`. Only `.permissionDenied` produces `.savePanel`.
5. **Gap 5: the lease request must name the destination.**
   - `writerWritesOnlyInsideLease` records the requests. A direct plan for a root-backed source asserts `requests == [.root(rootID, file: <destination folder's planned file>)]`, which is covered by the same Access Root.
   - On the panel-replace path it also asserts `held > 0` at `.move`.
6. **Gap 6: Save Annotated Copy enablement.**
   - Add `annotateSaveEnablement` (unit, S2): `canSaveAnnotatedCopy` is false outside the mode, false with `marks == []` (including after undoing back to empty), and true with one mark. `saveAnnotatedCopy()` while disabled starts nothing, and the host records no save request.
   - Extend `issue690BrowsingMenuItemsDisabled`: the Save Annotated Copy item is disabled with no marks and enabled with one.
7. **Defect: the `WriteStep.release` row.** Release is non-throwing. `.release` is dropped from the failure-injection steps in the at-any-step law. A separate assertion in `writerWritesOnlyInsideLease` checks that after a successful write the copy exists and `acquired == released`.

**Adversary status:** 6 of 6 gaps closed by applying the named cases. A second attack round was not run, because each fix is the adversary's own minimal case.

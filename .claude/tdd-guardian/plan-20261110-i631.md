# TDD Plan: #631 P0-2 Package coverage gate in CI

## Work Items

### WI-1: Parse, merge, and enforce Package LCOV
- **Description**: Build a deterministic Node merger and reporter for the two Package shards. Bind artifact metadata to the expected commit, run, attempt, toolchain, binary and profile; compare executable-line and function counts as integers. Inventory every production Swift file under the four MadoKit targets, with only committed reviewed no-executable-code exceptions.
- **Acceptance criteria**:
  - [ ] Complementary line and function hits merge, overlapping locations count once, source paths normalize to package-relative paths, and incompatible line/function mappings fail.
  - [ ] Missing or malformed artifacts, a missing shard, stale or mismatched provenance, duplicate/conflicting records, zero module or package denominators, and unexplained absent production files fail closed.
  - [ ] Every production module and the whole Package require exact 100% executable lines and functions; integer comparisons prevent rounded near-100% values passing.
  - [ ] The report gives module/package hit and total counts, uncovered locations, reviewed exclusions, statements as an explicitly line-based LCOV proxy, `branches unmeasured`, `App/ excluded`, the ImageSourceHeader loop-exit throw hit count, and binary/profile metadata.
- **Required tests**:
  - Real temporary LCOV shard files demonstrate complementary union and overlapping hit aggregation, including path normalization and duplicate rejection — assertion level: Level 1 output and Level 2 read-back; unit/contract lane, S5 merge conservation/idempotence.
  - Fixtures with malformed/missing/stale/mismatched profiles, source inventories, mapping conflicts, zero denominators, and near-100% fractions exit nonzero with precise diagnostics — assertion level: Level 1 output; contract lane, S2/S3.
  - Passing and failing report fixtures verify exact counts, uncovered source locations and all metric/exclusion labels — assertion level: Level 1 output; contract lane, S1/S3.

### WI-2: Produce isolated, attributable coverage artifacts in each existing Package shard
- **Description**: Add a shard export command and minimal workflow steps for the non-UI and serialized MacUI jobs. Use a fresh profile after any cache restore, coverage-specific cache keys, `--enable-code-coverage`, each shard's own test binary, and an uploaded LCOV plus metadata artifact. Preserve both watchdogs and their test selection.
- **Acceptance criteria**:
  - [ ] Each of the two existing macOS jobs emits the expected artifact only after its own test process and LLVM export succeed; missing or incompatible profile/binary fails the job.
  - [ ] A cache restore cannot reuse a stale profile; cold dispatch uses fresh build directories/profiles; cache keys for instrumented builds are separate from uninstrumented keys.
  - [ ] Non-UI skip pattern, MacUI `--no-parallel`, watchdog deadlines, and existing log uploads remain intact; no third macOS Package run is added.
  - [ ] Artifacts state commit/run/attempt/toolchain, binary and profile identity plus production source/mapping inventory, suitable for WI-1 validation and ten-run audit.
- **Required tests**:
  - Workflow contract tests inspect and execute exported shell/Node steps on real temporary files, proving two distinct shard exports, profile cleanup, cache-key separation, unchanged selection/watchdogs, and failure propagation — assertion level: Level 1 output and Level 2 filesystem effects; contract lane, S2/S3.
  - A local Package coverage run under `scripts/heavy-lock.sh` produces real LCOV and profile/binary metadata for the merge/gate path — assertion level: Level 3 real integration, S1.

### WI-3: Aggregate in Linux and bind the required Walking skeleton verdict

## Risks & Assumptions
- `swift test --enable-code-coverage` produces a package test profile and executable suitable for `llvm-cov export`; the export must prove binary/profile compatibility, not merely file existence.
- LCOV function identity may include names and start/end lines; the merger must reject incompatible mappings before unioning counters.
- Every production Swift file belongs to one of MadoCore, MadoApplication, MadoInfrastructure, or MadoMacUI; any no-executable-code exception requires an explicit committed, reviewed entry and must not hide executable mappings.
- The amended #631 item 1 is an enforcement precondition delegated to the CI runner: ten predeclared cold runs on one SHA and toolchain must all pass, with ImageSourceHeader loop-exit throw hit at least once in each; no retries or discarded runs. This local work cannot claim that evidence.
- P0-02 is tooling and has no separate feature-ledger row; implementation commits cite `P0-02` and `#631`.

## Deferred / Out of Scope
- App/ xcresult coverage, independent Swift statement or branch coverage, historical trend, separate changed-line gate, branch-protection changes.
- Any App or Package source/product change, retry/quarantine, changes to local unit or owner-gates lanes, and the delegated CI dispatch/push itself.

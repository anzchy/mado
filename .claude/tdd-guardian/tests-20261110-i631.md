# Test Matrix — #631 Package coverage gate

Plan: `plan-20261110-i631.md`. All cases use real temporary files and the real Node CLI unless the case names a native tool boundary. No production Swift or App target is changed.

## WI-1 — Unit: Package LCOV merger and exact gate

**Law**: For a fixed mapping, merged hit counts equal the sum of shard counts, while each executable line and function contributes exactly one denominator unit. Reordering shards leaves the result unchanged. A missing or inconsistent mapping must fail before a percentage is reported.

### Case: complementary and overlapping hits conserve counts
- **Category**: property
- **Lane**: unit
- **Spec level**: S5 — merge conservation and commutativity over generated nonnegative counters and distinct line/function keys (use `fast-check`).
- **Input**: Two valid shard LCOV records with the same mapping; generated counters on three lines and two functions, including zeros and overlap, in either shard order.
- **Expected output**: Each location's merged hit count equals the two inputs' sum; denominator stays three lines/two functions; pass iff all five sums are positive, independent of shard order.
- **Observable side effect**: Report file contains merged counts and verdict.
- **Assertion strategy**: Level 1 — parse the report and compare exact per-location and aggregate integers; Level 2 — read the written report.
- **Mock boundary**: none — real parser, merger, gate, and temporary files.
- **Refactor that would break this**: Changing the public report schema or arithmetic; an internal function rename does not.

### Case: path normalization preserves file identity and blocks escape
- **Category**: boundary
- **Lane**: unit
- **Spec level**: S2 — absolute workspace path, `./` path, normalized relative path, and outside-repository path.
- **Input**: The same source named by `/checkout/Packages/MadoKit/Sources/MadoCore/A.swift` and `Packages/MadoKit/Sources/MadoCore/./A.swift`; then `/other/A.swift`.
- **Expected output**: First two map to one file/one denominator; outside path fails with the offending `SF` path.
- **Observable side effect**: No passing report for invalid input.
- **Assertion strategy**: Level 1 — assert one source entry and exact denominator, then nonzero CLI exit plus diagnostic.
- **Mock boundary**: none — real parser and temporary files.
- **Refactor that would break this**: Changing accepted path semantics, not a helper rename.

### Case: inconsistent mappings and duplicate records fail closed
- **Category**: guard
- **Lane**: unit
- **Spec level**: S3 — line-set mismatch, function-name/start-line mismatch, duplicate `DA`, duplicate `FN`, and inconsistent LCOV summary records.
- **Input**: A passing pair mutated in one field per subcase; include duplicate source record within one shard.
- **Expected output**: Every mutation fails with a field-specific diagnostic; no percentage pass line is emitted.
- **Observable side effect**: No success report.
- **Assertion strategy**: Level 1 — nonzero exit, diagnostic names the mismatched file and key, success marker absent.
- **Mock boundary**: none — real files and CLI.
- **Refactor that would break this**: Altering validation behavior; internal parser structure can change.

### Case: missing, malformed, stale, and cross-run provenance cannot pass
- **Category**: failure
- **Lane**: integration
- **Spec level**: S3 — one absent artifact or metadata field, malformed JSON or LCOV, wrong SHA/run/attempt/toolchain, bad binary/profile hash, empty profile, and wrong shard label at a time.
- **Input**: Valid two-shard artifact directory with one named corruption per subcase and expected CI identity.
- **Expected output**: Each corruption exits nonzero before a coverage pass; provenance diagnostic identifies the mismatch.
- **Observable side effect**: No passing gate report.
- **Assertion strategy**: Level 1 — execute real CLI, assert status and failure text; Level 2 — inspect absence of a pass report.
- **Mock boundary**: none — real artifact files and crypto verification.
- **Refactor that would break this**: Only a behavioral change that accepts bad evidence.

### Case: full source inventory and zero denominators
- **Category**: guard
- **Lane**: integration
- **Spec level**: S3 — missing production Swift source, exception without exact reviewed path/reason, unexpected mapped source, zero-line module, zero-function module, and empty package.
- **Input**: Temporary four-module source tree and matching LCOV, removing one source or its mapping at a time; one reviewed no-code exception fixture.
- **Expected output**: Missing/extraneous/zero cases fail; exact reviewed exception passes only when it has no executable mapping and is printed as an exclusion.
- **Observable side effect**: Report names exclusions or error.
- **Assertion strategy**: Level 1 — exact file inventory and module totals in output; nonzero exit for each invalid case.
- **Mock boundary**: none — real filesystem inventory.
- **Refactor that would break this**: Changing which production files count, not internal traversal.

### Case: exact threshold and complete report
- **Category**: boundary
- **Lane**: unit
- **Spec level**: S2 — 100/100 and 9,999/10,000 lines plus one uncovered function.
- **Input**: Four modules with positive denominators; passing fixture and two near-pass mutations.
- **Expected output**: Only exact equality passes. Failing output lists module and package integer numerators/denominators, uncovered file:line and function; all reports label statement count as an LCOV line proxy, `branches unmeasured`, and `App/ excluded`.
- **Observable side effect**: Human report and CI step summary, including profile/binary hashes and the ImageSourceHeader loop-exit throw hit count.
- **Assertion strategy**: Level 1 — exact status and report values, no rounded pass; Level 2 — read report/summary.
- **Mock boundary**: none — real report generation.
- **Refactor that would break this**: Report contract or threshold semantics, not layout helpers.

### Case: loop-exit throw evidence follows source and LCOV counts
- **Category**: boundary
- **Lane**: unit
- **Spec level**: S2 — throw moves between two line numbers; its DA count is 0, 1, and 3.
- **Input**: Tiny `ImageSourceHeader.swift` fixtures containing the loop-exit `throw`, with one inserted line in the second source, and otherwise identical LCOV mappings and metadata.
- **Expected output**: Report locates the throw by source content, not a fixed line number, and prints exactly the merged DA hit count for that line in each fixture. An absent or ambiguous throw fails evidence validation.
- **Observable side effect**: Per-run diagnostic report gives source line and hit count.
- **Assertion strategy**: Level 1 — assert line and exact count for all fixtures; nonzero exit on ambiguous/missing throw.
- **Mock boundary**: none — real source and LCOV fixture files.
- **Refactor that would break this**: Moving or changing the throw evidence; an internal locator rename does not.

### Case: same file names with divergent source digests or mapping inventory fail
- **Category**: guard
- **Lane**: integration
- **Spec level**: S3 — identical path sets but one changed source byte, one changed mapping line, and one changed function start line.
- **Input**: Two otherwise valid shard artifacts with one content or mapping digest changed at a time.
- **Expected output**: Merge exits nonzero before reporting a coverage pass, with file and digest or mapping diagnostic.
- **Observable side effect**: No passing report.
- **Assertion strategy**: Level 1 — process status and diagnostic; Level 2 — inspect report absence.
- **Mock boundary**: none — real artifact bytes and metadata.
- **Refactor that would break this**: Accepting divergent source/mapping evidence.

## WI-2 — Unit: shard export and Package-job workflow contract

**Law**: An artifact can be published only if the test process, a fresh profile, the matching binary and LLVM export succeed; the exported metadata identifies exactly the files uploaded. Clearing coverage state is idempotent and occurs after restore, before test.

### Case: a real local Package shard exports attributable LCOV
- **Category**: success
- **Lane**: integration
- **Spec level**: S1 — one local coverage-enabled Package run under `scripts/heavy-lock.sh`.
- **Input**: Actual `swift test --enable-code-coverage` result, package test binary, and profile.
- **Expected output**: Export succeeds; LCOV contains production `SF`, `DA`, `FN`, and `FNDA`; SHA-256 hashes match the binary/profile bytes; metadata identifies toolchain, commit, run, attempt and shard.
- **Observable side effect**: Artifact directory with LCOV and JSON; exporter exits nonzero on a deliberately mismatched profile/binary pair.
- **Assertion strategy**: Level 3 — run real Swift/LLVM path; Level 2 — hash and read artifact files.
- **Mock boundary**: none — real SwiftPM and LLVM tools.
- **Refactor that would break this**: Breaking artifact compatibility or provenance, not script names.

### Case: export failure cannot yield a successful artifact
- **Category**: failure
- **Lane**: integration
- **Spec level**: S3 — missing profile, empty profile, missing binary, unsupported LLVM export, and missing required run identity.
- **Input**: Temporary artifact paths with one missing/corrupt prerequisite at a time.
- **Expected output**: Nonzero exit and no publishable complete artifact.
- **Observable side effect**: No complete metadata/LCOV pair.
- **Assertion strategy**: Level 1 — CLI exit and diagnostic; Level 2 — inspect artifact directory.
- **Mock boundary**: LLVM process may be replaced only for deterministic error injection; paired integration test: “a real local Package shard exports attributable LCOV”.
- **Refactor that would break this**: Accepting an incomplete export; internal command construction can change.

### Case: both existing jobs run isolated coverage with unchanged test selection
- **Category**: state
- **Lane**: contract
- **Spec level**: S5 — the workflow state transition is restore → clear profile → test → export → upload; cold skips restore but still clears profile.
- **Input**: Parse the checked-in workflow for non-UI and MacUI jobs; execute each extracted cleanup shell against a temporary cache-restored profile.
- **Expected output**: Each job uses `--enable-code-coverage`, coverage-only cache key, own export and fail-on-missing upload; cleanup removes stale profile, preserves non-profile cache; non-UI skip, MacUI `--no-parallel` and skip, watchdog limits/log upload remain.
- **Observable side effect**: Temporary profile removed and unrelated cache file retained.
- **Assertion strategy**: Level 1 — exact resulting step order and command semantics; Level 2 — filesystem state after shell execution.
- **Mock boundary**: GitHub Actions runner unavailable locally; paired integration test: “a real local Package shard exports attributable LCOV” covers native tool path, CI dispatch evidence covers hosted path.
- **Refactor that would break this**: Moving cleanup after test or loosening upload/test selection; harmless YAML formatting should not.

## WI-3 — Unit: Linux aggregation and Walking skeleton enforcement

**Law**: For native PR/main runs, any unsuccessful coverage result must make the required verdict fail once enforcement is on; a trusted docs-only classification may pass only with every native/coverage job skipped. A filtered dispatch is never formal Package evidence.

### Case: required verdict accepts only complete enforced native success
- **Category**: boundary
- **Lane**: contract
- **Spec level**: S3 — success, failure, cancelled, skipped, and missing coverage result, plus current and historical trusted verdicts.
- **Input**: Execute the actual Walking skeleton shell with these result environments and trusted-base fixture variants.
- **Expected output**: Enforced native PR/main succeeds only on coverage `success`; all other results exit 1 before the old trusted verdict can pass; successful native case retains App verdict behavior.
- **Observable side effect**: Process status/stdout with coverage result.
- **Assertion strategy**: Level 1 — process exit and message for each result.
- **Mock boundary**: Trusted base is a committed historical script fixture because checkout/network is external; paired integration test: “Linux job downloads both shards and runs the real gate”.
- **Refactor that would break this**: Weakening the minimum, not changing script internals.

### Case: docs-only and filtered dispatch classifications remain precise
- **Category**: guard
- **Lane**: contract
- **Spec level**: S2 — trusted native=false with all skips; unexpected coverage success/failure; full cold dispatch; nonempty `swift_filter` dispatch.
- **Input**: Execute actual verdict shell and coverage report classifier with each environment.
- **Expected output**: Trusted docs-only passes only with coverage skipped; unexpected job outcome fails. Full cold dispatch is marked formal Package evidence if unfiltered; filtered dispatch is diagnostic and cannot satisfy formal coverage; neither can bypass required tests.
- **Observable side effect**: Status and explicit formal/diagnostic report text.
- **Assertion strategy**: Level 1 — process status and exact evidence classification.
- **Mock boundary**: None for verdict/classifier; hosted dispatch remains delegated.
- **Refactor that would break this**: Changing accepted evidence, not renaming variables.

### Case: pending rollout switch reports the gate without blocking
- **Category**: state
- **Lane**: contract
- **Spec level**: S2 — `false` pending switch and `true` enabled switch against the same old trusted verdict fixture.
- **Input**: Native PR/main with coverage `failure`, `cancelled`, `skipped`, or missing, evaluated under both one-line switch values.
- **Expected output**: Pending mode prints that Package coverage is not yet enforced and preserves the old trusted verdict; enabled mode exits 1 for every unsuccessful coverage result before an old trusted verdict can pass. Threshold remains exact 100% in the aggregation job in both modes.
- **Observable side effect**: Process exit and explicit rollout status output.
- **Assertion strategy**: Level 1 — exact status/message matrix from the actual Walking skeleton shell.
- **Mock boundary**: Historical trusted verdict fixture is a real committed script; paired integration test: “Linux aggregation consumes exactly two validated shard artifacts”.
- **Refactor that would break this**: Changing rollout semantics, not rearranging shell lines.

### Case: Linux aggregation consumes exactly two validated shard artifacts
- **Category**: failure
- **Lane**: integration
- **Spec level**: S3 — both valid, one missing, duplicate same shard, cross-run shard, and gate failure.
- **Input**: Actual aggregation command against temporary artifact directories, one mutation per case; workflow contract checks Linux job needs both Package jobs and download step.
- **Expected output**: Only two compatible distinct shards produce a report; all mutations exit nonzero; report upload happens even if gate fails and the required verdict observes aggregation result when enforcement is enabled.
- **Observable side effect**: Downloaded artifact tree, report and GitHub step summary.
- **Assertion strategy**: Level 1 — exit code/report content; Level 2 — file and summary read-back.
- **Mock boundary**: GitHub artifact service is outside local scope; paired integration test: “a real local Package shard exports attributable LCOV” validates producer, and delegated CI cold run validates hosted transport.
- **Refactor that would break this**: Accepting a missing or incompatible shard; internal file layout may change if contract stays intact.

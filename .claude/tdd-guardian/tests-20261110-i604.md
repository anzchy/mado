## Unit: CanvasWindowController sidebar presentation/load path (WI-1, WI-2)

**Law**: After a failed child read, readable-root reachability survives Retry; the newest navigation alone owns sidebar selection, topology, and counts.

Tests use real controller, session, GridShellView, SidebarFolderBrowser, FileAccess and temporary directories. An existing adapter seam may inject a controlled filesystem listing/read failure or hold a result; delegate unaffected operations to real SystemSidebarFolderEnumerator/FolderBrowser. Do not mock the controller, loader, tree, monitor or model. This verifies presentation policy under a boundary failure, not OS permission delivery. A new seam solely for mocking is prohibited.

### Case: issue604FailedChildKeepsParentAndReadableSibling — FIRST RED (WI-1)
- **Category**: failure
- **Lane**: integration (existing App `app-red` lane)
- **Spec level**: S3 — exact collapse reported in #604.
- **Input**: Real Parent containing Locked and Readable; open Parent to completed tree, click Locked; Locked listing and scan fail while Parent remains readable. Parent/Readable each contain a different real PNG count.
- **Expected output**: Failed page visible; Parent at depth 0, Locked selected at depth 1, Readable unselected at depth 1. No duplicate rows. Locked shows visible `—` without partial numeric count. Parent/Readable stay usable and do not show failure dash.
- **Observable side effect**: Visible AppKit tree rows, selected row, count labels and failure page.
- **Assertion strategy**: Level 4 — assert URL/depth/current tuples and failed-state visibility; Level 1 — assert dash/count text. Existing implementation must fail the topology assertion showing Locked alone at L0.
- **Mock boundary**: Controlled filesystem listing/scan error, all successful operations real.
- **Paired integration test**: `sidebarListingCountsRealDirectImagesAndKeepsLease` (real enumerator/filesystem) and case `issue604ReadableChildRetainsExistingProjection` (real App path).
- **Refactor that would break this**: Removing parent/siblings during child failure or assigning the failure dash to the wrong row.

### Case: issue604RetryKeepsFailureTreeThenRestoresRealCount (WI-2)
- **Category**: state
- **Lane**: integration (App `app-red`)
- **Spec level**: S5 — reachability invariant across fail → Retry reading → fail → Retry reading → success.
- **Input**: The failed-child fixture above. Hold each Retry boundary until assertions; first retry fails, second succeeds with three PNGs.
- **Expected output**: Throughout Retry reading and repeated failure, Parent stays L0, Locked selected beneath it, Readable remains at sibling depth. During reading Locked has no numeric count; on failure visible dash returns. On success current-child real count becomes 3. Successful final topology follows baseline projection rather than adding an out-of-scope sibling guarantee.
- **Observable side effect**: Tree and page state before and after each explicit release.
- **Assertion strategy**: Level 4 — assert root/sibling reachability at every held transition and after repeated failure; Level 1 — assert loading count absence, failure dash, and final count 3.
- **Mock boundary**: Controlled filesystem failure and completion gate; real operations after release.
- **Paired integration test**: `issue604ReadableChildRetainsExistingProjection` and `sidebarListingCountsRealDirectImagesAndKeepsLease`.
- **Refactor that would break this**: Clearing preserved topology at Retry start, retaining the dash after success, or installing stale counts during reading.

### Case: issue604LateOldResultsCannotRebuildNewTree (WI-2)
- **Category**: state
- **Lane**: integration (App `app-red`); focused loader cancellation may also use package `unit`/`swift-red`.
- **Spec level**: S5 — latest navigation ownership invariant across controlled out-of-order completion, including ABA revisit.
- **Input**: Hold an old listing or recovery listing for Locked, switch to Readable and complete it, then release old successful listing/failure and old count. Include revisit to distinguish generation from URL-only ownership. Gates deliberately permit late adapter return even after cancellation.
- **Expected output**: Newest selected folder, exact new tree and real counts remain unchanged after old work actually returns; old failure cannot recreate failed tree or attach dash to current folder.
- **Observable side effect**: Visible rows/counts after explicit old-result completion, not merely before release.
- **Assertion strategy**: Level 4 — capture new tree ownership state, release old work, await its completion signal, assert unchanged tree/current folder/counts. Existing `sidebarABARevisitRejectsStaleBlockedCount` covers count ABA additionally.
- **Mock boundary**: Controlled asynchronous filesystem result timing; real successful listing/count payloads.
- **Paired integration test**: `issue604ReadableChildRetainsExistingProjection`; existing `sidebarABARevisitRejectsStaleBlockedCount` exercises the real controller generation guards with a held boundary.
- **Refactor that would break this**: Dropping generation/cancellation guards, checking only folder URL, or publishing the root recovery tree after navigation ownership changed.

# Plan — #507 fix round 2: symlinked folders take the folder panel

Source: `~/.picsee/herdr/opus-imple-1/i507-fix2-brief.md`. Owner decision 2026-11-07, verbatim choice
「Same as a plain folder (Recommended)」: a folder reached through a symlink is handled exactly like a plain folder.
Drop and Open With / `open -a` of a single directory (link or plain) go to the same folder panel prompt a plain
folder drop takes, with the canonical target preselected. Only the panel creates an Access Root (ADR-006, ADR-008,
GLOSSARY.md:99).

Base: origin/main 8c84c9a0; branch head before this round ea232373 (rebased b93be9f6).

## Work items

### WI-1: FileAccess classifies a single native selection by directory metadata, off the MainActor
- New `FileAccess.deliveredFolder(_ url: URL) -> URL?` (actor-isolated, so never on the MainActor — opus M2).
  Holds the selection's scope (or requires process readability when no scope starts), checks real directory
  metadata (follows symlinks), returns the canonical target as a directory URL; nil for a file, a dangling link,
  a non-file URL or an unreadable selection. Balanced start/stop.
- AC: a raw directory symlink (no trailing slash) → canonical target; plain folder without a hint → itself,
  canonical; image file → nil; dangling link → nil; non-file URL → nil; unreadable unstartable selection → nil;
  every started scope is stopped exactly once; no Access Root record is created.
- Tests: package `Issue507DeliveredFolderClassificationTests.swift`.

### WI-2: drop / Open With of a single folder goes to the folder panel prompt; delivered admission removed
- `openInput`: for a single URL, `await services.files.deliveredFolder(url)`; when it names a directory, hand
  `[target]` to `session.openInput`, which classifies `.folder` and calls `promptForInputFolder(target)`
  (the existing plain-folder route: "Browsing Needs Folder Access" → NSOpenPanel with `directoryURL = target`).
- Test seam: `CanvasWindowController.folderGrantPromptOverride` replaces only the `FolderGrantPrompt.request`
  call, so tests see the prompted folder and answer (grant = call the selection closure, cancel = never call).
- AC: drop of raw link, drop of plain folder, open -a of link and plain directory URL each reach the prompt once,
  with the canonical target; before the answer no Access Root record, no roots store file, no recent entry;
  after the simulated grant of the target the three-image grid completes within 2 s with no second prompt and no
  attached sheet, recents show `actual`, exactly one record; cancelling leaves no root, no recent, no bookmark
  store file and no scan.
- Tests: App `Issue507AliasFolderScanTests.swift` (new delivered-folder test + cancel test; the two
  "drop/Open With" cases leave the no-sheet list).

## Risks
- Under the real sandbox the drop's extension may not let `deliveredFolder` stat the target; then the input falls
  back to the old classification (unchanged plain-folder behaviour for hinted URLs). Device smoke decides.
- `promptForFolder` returns early while any sheet is attached (pre-existing).

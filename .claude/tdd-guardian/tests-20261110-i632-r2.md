## Unit: Coverage export for split runs

**Law**: Current-run coverage conserves both tested partitions and binds them to the exact tested bundle; discovery cannot switch to another binary. Every external coverage operation terminates within its deadline or fails without publishing successful coverage.

### Case: Export uses the captured tested bundle without Swift rediscovery
- **Category**: state
- **Lane**: integration
- **Spec level**: S5 — identity of the tested executable is preserved across run capture and export.
- **Input**: Completed current-run metadata points to tested bundle A and its two captured profiles; another bundle B exists at a discoverable default path. Put a hostile external Swift executable on PATH that records any invocation and fails immediately.
- **Expected output**: Export succeeds from A's captured metadata and profiles; exported source identities match A; no Swift discovery invocation occurs.
- **Observable side effect**: One current LCOV for tested bundle A, no discovery marker and no bundle-B coverage.
- **Assertion strategy**: Level 1/2 — run actual exporter against real temporary files; assert status, parsed LCOV identities and absence of hostile Swift marker. External LLVM fixture must inspect input bundle identity and derive distinct report identities from A and B; real LLVM pairing below verifies actual tool compatibility.
- **Mock boundary**: External Swift and LLVM executables only, representing the system tool boundary.
- **Paired integration test**: Real split package and LLVM coverage acceptance in the original matrix; it must verify exporter consumes the captured tested-bundle path.
- **Refactor that would break this**: Rediscovering a potentially different binary or losing captured executable identity; internal helper names do not matter.

### Case: Hanging coverage merge or export is bounded and fails without a report
- **Category**: failure
- **Lane**: integration
- **Spec level**: S3 — unbounded coverage commands are the exact surviving adversarial failure mode.
- **Input**: Valid completed partition metadata, tested bundle and profiles; seed old successful LCOV. In separate scenarios, external profile merge or external LCOV export starts a TERM-resistant detached helper and hangs under a short test deadline.
- **Expected output**: Each scenario exits 124 within configured operation budget plus bounded capture/cleanup allowance; names the timed-out operation; no retry and no successful report publication.
- **Observable side effect**: Owned leader/helper PIDs are dead; timeout evidence exists; neither old nor partial LCOV qualifies as current success.
- **Assertion strategy**: Level 3/2 — execute real repository watchdog and OS process operations with external tool fixtures; measure elapsed bound, assert exit/diagnostic, inspect recorded PID liveness and invoke the normal coverage consumer to prove rejection.
- **Mock boundary**: External LLVM executable only; use real child spawning, filesystem and watchdog.
- **Paired integration test**: Existing watchdog detached-helper/orphan-helper timeout tests, plus Real split package and LLVM coverage acceptance for real LLVM operation success.
- **Refactor that would break this**: Losing bounded operation cleanup or fail-closed report publication; internal decomposition is tolerated.

## Unit: PicseeMacUI/GridShellView footer status (name slot `grid.current-file-status`, count slot `grid.folder-count`)

**Law**: The rendered footer is a pure function of (read flag, page) and the stored name/count:
`name = (reading || failed || lost || empty) ? "–" : storedName`;
`count = reading ? "Reading…" : failed ? "Read incomplete" : lost ? "Unavailable" : storedCount`
(empty keeps `storedCount`), where `lost = tree visible && tree current folder accessLossCause != nil`,
`empty = emptyFolderView visible`, and `storedName` / `storedCount` are exactly the last `setCurrentFile` /
`setSearchStatus` (or `""` after `setSearchTerm("")`) values — derived text never overwrites them. Consequence: any
transition sequence that ends in normal mode renders the last stored values (recovery invariant), and the footer is
invariant under `toggleSidebar()` (layout idempotence).

### Case: footerStatusTransitionsRestoreStoredFooter (law)
- **Category**: property / state
- **Lane**: unit
- **Spec level**: S5 — an invariant across arbitrary state transitions, checked against an oracle model; covers
  recovery, precedence and "stored values never overwritten" in one claim.
- **Input**: seeded deterministic generator (SplitMix64, fixed seed list, 128 sequences x 8 ops; seed + op list in
  every failure message). One fresh shell per sequence at 1280x772. Operation alphabet:
  `reading(Bool)`, `readFailed(Bool)`, `showLost(cause)` (cause from `causes`), `showTree` (non-lost current),
  `showFolder("待整理")`, `clearTree` (`folderTree.clear()` then `setSearchTerm("")`), `empty(Bool)`
  (`setEmptyFolderState`), `file(k)` (`setCurrentFile("f\(k).png")`), `count(k)` (`setSearchStatus(k, "")`),
  `searchTerm("")`. Every sequence is followed by the forced tail `reading(false), readFailed(false), showTree, empty(false)`.
- **Expected output**: after **every** op, the rendered name/count equal the oracle (the Law line above), with
  `expectHidden` when the oracle value is `""` and `expectSlot` otherwise. Oracle model: reading and failed are mutually
  exclusive, the last `true` wins, and `false` clears only its own flag (mirrors `setReadingStatus`/`setReadFailedStatus`);
  `lost` is true only after `showLost` and false after `showTree`/`showFolder`/`clearTree`; `storedCount = ""` after
  `searchTerm("")`/`clearTree`. The forced tail must render the last stored name/count exactly.
- **Observable side effect**: rendered footer at each step.
- **Assertion strategy**: Level 1 — rendered values compared to the model at each step.
- **Mock boundary**: none — real implementation
- **Paired integration test**: n/a
- **AC covered**: AC5, AC6 (all four recovery paths as ops), AC7, AC2 (late file/count while lost).
- **RED/guard**: RED before fix (the first `showLost` step diverges from the oracle).
- **Refactor that would break this**: only a change to the precedence rule itself, which is the spec.

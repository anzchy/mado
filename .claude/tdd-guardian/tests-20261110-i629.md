## Unit: appcast.test.mjs#isMadoFeed

**Law**: Item permutation does not change feed validity; a single invalid item invalidates the entire feed at every position. This is covered by an S6 relation over the exact two-item fixture and its permutations. No random property library is needed for this exhaustive two-item domain; do not add fast-check merely for this finite relation.

### Case: exact #627 regression
- **Category**: failure
- **Lane**: contract
- **Spec level**: S3 — reproduces the named real failure.
- **Input**: Byte-identical feed from `origin/appcast-mado/mado-v0.0.1-rc.2:appcast-mado.xml`; first build 1740, RC URL `mado-v0.0.1-rc.2/Mado-0.0.1.dmg`, then final build 1691.
- **Expected output**: `isMadoFeed(fixture) === true`; before correction it is false because only the final tag URL is accepted.
- **Observable side effect**: none.
- **Assertion strategy**: Level 1 — assert true and assert fixture contains the real RC URL and expected builds, preventing a final-only substitute fixture.
- **Mock boundary**: none — real implementation.
- **Paired integration test**: not applicable.
- **Refactor that would break this**: Removing supported RC tags or failing to inspect the real fixture content; internal implementation renames do not alter the contract.

### Case: final and positive RC boundaries
- **Category**: boundary
- **Lane**: contract
- **Spec level**: S2 — partitions final, smallest RC, and multiple-digit RC.
- **Input**: Exact same-version URLs with suffixes absent, `-rc.1`, `-rc.2`, `-rc.10`, and `-rc.12345678901234567890`; retain exact HTTPS host/repository and `Mado-0.0.1.dmg` filename.
- **Expected output**: true for each feed.
- **Observable side effect**: none.
- **Assertion strategy**: Level 1 — assert the returned Boolean for each explicit URL; RC digits are syntax, not a JavaScript number conversion.
- **Mock boundary**: none — real implementation.
- **Paired integration test**: not applicable.
- **Refactor that would break this**: Restricting RCs to one digit, using a numeric upper bound, or rejecting documented final tags.

### Case: consistent version renaming
- **Category**: property
- **Lane**: contract
- **Spec level**: S6 — validity is preserved by consistent version renaming, and lost when only one version component changes.
- **Input**: Rename a valid RC feed from shortVersion `0.0.1` to `1.2.3`, simultaneously changing the item title, `sparkle:shortVersionString`, release tag to `mado-v1.2.3-rc.4` and asset to `Mado-1.2.3.dmg`; then mutate only the tag to `mado-v1.2.4-rc.4`. Exercise real generation for both `0.0.1` and `1.2.3` final/RC releases as well.
- **Expected output**: Original and consistently renamed feeds return true; the mismatched renamed tag returns false. Generated feeds for both versions remain valid.
- **Observable side effect**: none.
- **Assertion strategy**: Level 1 — assert true after consistent renaming and false after the one-component mutation. This defeats a special-case implementation accepting RCs only for `0.0.1`.
- **Mock boundary**: none — real implementation.
- **Paired integration test**: not applicable.
- **Refactor that would break this**: Hardcoding the first release version or ignoring shortVersion/tag correspondence.

### Case: malformed or mismatched RC URLs
- **Category**: guard
- **Lane**: contract
- **Spec level**: S2/S3 — rejects malformed suffix partitions and the identity/version mismatch failure modes.
- **Input**: RC suffixes `-rc.0`, `-rc.01`, `-rc.`, `-rc.-1`, `-rc.1.2`, `-RC.2`, `-beta.2`, `-rc.2extra`; same RC suffix with release tag version `0.0.2`, filename version `0.0.2`, HTTP scheme, foreign host, `github.com.example.com`, foreign repository, wrong product filename, `?download=1`, `#fragment`, or `/extra`.
- **Expected output**: false for every mutated feed. Also reject a malformed shortVersion such as `0x0x1` paired with a matching-looking URL, preventing unescaped regex interpolation from treating version dots as wildcards.
- **Observable side effect**: none.
- **Assertion strategy**: Level 1 — assert false with the offending URL in the assertion message.
- **Mock boundary**: none — real implementation.
- **Paired integration test**: not applicable.
- **Refactor that would break this**: Loose substring checks, unanchored URL matching, unescaped version interpolation, or acceptance of arbitrary prerelease syntax.

### Case: mixed-feed permutation and rejection propagation
- **Category**: property
- **Lane**: contract
- **Spec level**: S6 — compares outputs under exhaustive permutation and single-item mutation transformations.
- **Input**: Both orders of exact fixture RC/final items; then both orders after corrupting the RC URL and after removing its signature.
- **Expected output**: Both valid permutations return true; every corrupted permutation returns false.
- **Observable side effect**: none.
- **Assertion strategy**: Level 1 — assert returned validity under each transformation; constant true and first-item-only implementations fail.
- **Mock boundary**: none — real implementation.
- **Paired integration test**: not applicable.
- **Refactor that would break this**: Inspecting only the first or last item, or exempting RC entries from required signature checks.

## Unit: appcast.mjs#updateAppcast and feed contract

**Law**: Repeating an upsert with the same release is idempotent and retains existing entries byte for byte (S5).

### Case: real generator contract and idempotence
- **Category**: state
- **Lane**: contract
- **Spec level**: S5 — output validity and unchanged output across repeated generation.
- **Input**: Real first-release fixture; insert build 1740 with shortVersion `0.0.1`, valid 64-byte signature, fixed pubDate, positive length and exact final URL; repeat separately with exact RC URL `mado-v0.0.1-rc.2/Mado-0.0.1.dmg`.
- **Expected output**: Each generated feed validates, preserves the old item text exactly, has builds `[1740,1691]`, and a second identical upsert equals the first output.
- **Observable side effect**: none — in-memory real generator output.
- **Assertion strategy**: Level 1 — assert validity, version list, original-item equality and repeated-output equality. A generator returning the original fixture fails the version assertion.
- **Mock boundary**: none — real implementation.
- **Paired integration test**: not applicable.
- **Refactor that would break this**: Altering emitted URLs/required fields, losing history, duplicating upserts or changing ordering; internal refactors remain free.

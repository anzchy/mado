# TDD Plan: Viewer Recognise Text (#687 slice B)

## Work Items

### WI-1: Window-scoped recognition and clipboard state
- **Description**: Adapt the existing `TextRecognitionService` for one viewer window. Start explicit recognition from the shown decoded image, keep work off the main actor, and admit results only while the same image and window remain current. Own a replaceable notice/panel state and a pasteboard port.
- **Acceptance criteria**:
  - [ ] A non-whitespace result copies one plain string and reports its `String.count` grapheme count and engine label, including the cloud label carried by the result type.
  - [ ] Empty and whitespace-only results leave pasteboard contents and `changeCount` unchanged and produce the non-clickable no-text notice; non-cancellation errors also leave it untouched and produce the error notice; cancellation produces no notice.
  - [ ] Image change or window close cancels/drops an in-flight result; a repeated invocation replaces prior notice state; busy state lasts only while work is admitted.
  - [ ] A real `NSPasteboard` integration test uses a private named pasteboard, never `.general`.
- **Required tests**:
  - Fake gated provider and fake pasteboard: success, grapheme count, engine labels, empty/whitespace, error, cancellation, stale image, close, repeat and busy state; assert resulting notice and pasteboard state — assertion levels: Level 1 and Level 2.
  - App-hosted private named `NSPasteboard` integration: found text yields one plain string; no-text preserves `changeCount` and contents — assertion level: Level 3.

### WI-2: Pinned notice and editable panel

  - [ ] Notice dismisses about five seconds after pointer exit, but remains while hovered. A new recognition replaces the previous surface. A long result scrolls within a fixed 150 pt text view; a five-digit count stays on one line; at minimum window width the whole panel remains visible by shrinking to content width minus 40 pt.
- **Required tests**:

## Risks & Assumptions
- `TextRecognitionService` accepts `Data`, while viewer pixels are a `CGImage`; encode the decoded source at full resolution off-main before passing it, or use a narrow API addition if unavoidable. Do not use a screen render.
- The package provider may internally bound Vision input size. That does not justify sending a displayed thumbnail from the viewer; note residual quality/memory risk in handoff.
- Existing `CanvasWindowController` file fence permits only one stored property; prefer observation/window notifications and an extension, and document any unavoidable missing hook instead of crossing ownership fences.
- `NSPasteboard.general` is production-only. Tests use an injected fake or private named pasteboard to protect the user's clipboard.
- Full App runner under `~/Documents` can hang; follow the specified build-for-testing and app-lane fallback, with CI binding for that layer.

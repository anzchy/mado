## Unit: WI-1 SettingsPanelWindow + real SparkleUpdatePort

**Law**: Without a configured updater, control state is invariant through click attempts and leaving/reselecting Updates. This is a finite UI state-transition invariant (S5), checked directly with native controls; no property-testing dependency is needed to generate an unbounded domain.

### Case: Real no-feed Settings stays disabled after click and refresh
- **Category**: state
- **Lane**: integration (configured `app-red`, then full App lane)
- **Spec level**: S5 — disabling and the off state survive click and pane-reselection transitions.
- **Input**: Real `SparkleUpdatePort(infoDictionary: [:])`, real SettingsPanelWindow, real checkbox and Check Now; invoke performClick then leave/reselect update pane. Add empty and whitespace-only feed partitions if practical.
- **Expected output**: Both controls disabled before and after transitions; automatic checkbox off before/after click; port automatic preference false, canCheck false, last check nil.
- **Observable side effect**: No preference transition or update-check date appears.
- **Assertion strategy**: Level 3 + Level 4 — assert actual native control isEnabled/state and real port state. This must be the first recorded RED before production edits.
- **Mock boundary**: none — real Settings, no-feed SparkleUpdatePort; missing feed naturally prevents constructing external Sparkle.
- **Paired integration test**: This is the real integration case.
- **Refactor that would break this**: Only a change to public disabled/state behavior or removing the accessible control; private updater or Settings method renames do not matter.

## Unit: WI-1 CanvasWindowController folder-entry restoration

**Law**: S5 round-trip: entering a replacement folder then cancelling its reading preserves the prior waiting page's folder identity, cause, parent and visible footer.

### Case: t332CancelReadingRestoresLostAccessFooterAndSidebar
- **Category**: state
- **Lane**: integration (App bundle via `app-red`)
- **Spec level**: S5 — round-trip over both Choose Another Folder and Choose at New Location routes.
- **Input**: Existing RecoveryFixture, root A child One on page 26 with prior cause `.notFound`; snapshot original row/parent; arm gate on root B; `completeAccessFolderSelection(f.b, reselect: false/true)`; await reading blocked; click actual Cancel Reading; inspect immediately before gate release, then drain and check again.
- **Expected output**: Page 26 remains visible, waiting root/folder and `.notFound` restored; footer name visible `–`, count visible localized `Unavailable`, never `Reading…`; sidebar current URL is prior folder, cause `.notFound`, parent is original parent and children remain empty. Search/sort remain disabled. Both routes pass.
- **Observable side effect**: Native AppKit view tree returns to the prior lost page/sidebar and remains there after abandoned scan completion.
- **Assertion strategy**: Level 1/3 — actual rendered NSTextField values and visibility plus real controller/sidebar state. Existing App read gate controls timing rather than replacing controller or view.
- **Mock boundary**: Existing RecoveryFixture bookmark/mount system adapters and read gate simulate external unavailability; real filesystem fixture, AccessServices, controller, Session and native views remain in use. This test does not claim sandbox or physical volume behavior.
- **Paired integration test**: This is the App integration case covering the real restoration path; existing signed records referenced by ACCESS-04 cover device loss only, not this cancellation fix.
- **Refactor that would break this**: Changing product behavior to discard or substitute a lost waiting folder on cancelled navigation; private method renames do not.

## Unit: WI-2 GridShellView footer derivation

**Law**: S5 — rendered footer obeys reading > failed > lost > empty > stored, and deriving overrides never mutates stored text; exiting overrides restores latest stored state.

### Case: emptyFolderFooterShowsDashAndZeroImages with active search
- **Category**: boundary
- **Lane**: unit
- **Spec level**: S2 — empty/active search equivalence classes, blank/short/long stored file names, 1280×772 and 800×680, zero/two sidebar toggles.
- **Input**: Existing empty-page test inputs with term `""` or nonempty `"x"`; set search result count zero while actual folder-empty state is true. Include a long nonempty term where useful.
- **Expected output**: Empty page visible; exact name `–` and localized `0 images`, both shown and with enough width to avoid truncation; active term does not render a Search summary in page22 count.
- **Observable side effect**: Actual footer NSTextFields in real NSWindow/GridShellView.
- **Assertion strategy**: Level 1 — exact rendered text, visibility and frame widths through existing helpers.
- **Mock boundary**: None — real view implementation and in-memory preferences; no external service involved.
- **Refactor that would break this**: Letting a search summary override the empty page count or layout shrink it as though it were that summary.

### Case: footerStatusTransitionsRestoreStoredFooter search alphabet and oracle
- **Category**: property
- **Lane**: unit
- **Spec level**: S5 — extend existing seeded sequence domain with active search, force enter-empty/search/late-count/clear-term/exit-empty and read/lost combinations to exercise precedence and storage restoration.
- **Input**: Existing 128 seeded sequences, now including search(term,resultCount) operations in addition to normal counts, names, page visibility and reading/failure/loss. Guarantee at least one active-search operation while empty and normal-page recovery; preserve recovery coverage assertions.
- **Expected output**: Oracle count is Reading/Read incomplete/Unavailable/zero-images/stored summary by precedence; name is dash for any override. Once empty ends, stored summary/count reappears exactly; clearing term while empty keeps zero-images until empty ends.
- **Observable side effect**: Actual rendered footer after each state operation.
- **Assertion strategy**: Level 1 — compare every step's two rendered NSTextFields to the independent model; latest stored values are separate from displayed values.
- **Mock boundary**: None — real view. Existing deterministic SplitMix64 harness is retained under this brief's explicit law-model request; SwiftCheck is catalogued but adding a new dependency is outside this narrow fix.
- **Refactor that would break this**: Overwriting stored count with zero, giving search priority over empty, clearing stored summaries on layout, or changing priority among reading/failure/loss/empty.

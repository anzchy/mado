## Unit: RecogniseTextModel#start, openPanel, edit, copyEditedText, close

**Law**: A result may change the pasteboard exactly once if, and only if, it contains non-whitespace text and its window/image identity is still current. Invalidated, failed, cancelled and no-text runs conserve pasteboard `changeCount` and contents; a later result may never resurrect an invalidated run. This is an S5 invariant across state transitions.

### Case: success copies graphemes and preserves engine
- **Category**: success
- **Lane**: unit (App in-process)
- **Spec level**: S2 — on-device and cloud result classes, including one combining grapheme.
- **Input**: success results `e\u{301}中文` with intentionally wrong provider `characterCount=99`, then `A🙂` with on-device engine.
- **Expected output**: copied notices with counts 3 and 2; engine tags cloud and on-device; `panelText` is the result text after click.
- **Observable side effect**: fake pasteboard receives each result as one plain string; new notice replaces old notice.
- **Assertion strategy**: Level 1/2 — exact notice and pasteboard history, including `String.count` grapheme cluster claim.
- **Mock boundary**: recogniser and pasteboard port to make result and write deterministic.
- **Paired integration test**: `privateNamedPasteboardAndRealServiceRecogniseFixture`.
- **Refactor that would break this**: using `utf16.count`, trusting a stale result count, dropping the engine, or appending instead of replacing.

### Case: empty and whitespace preserve clipboard
- **Category**: boundary
- **Lane**: unit
- **Spec level**: S2 — empty string, spaces/newline/tab and Unicode whitespace.
- **Input**: results `""`, `" \n\t"`, `"\u{3000}"` after a sentinel clipboard value.
- **Expected output**: `.noText` with no engine tag; no panel can open.
- **Observable side effect**: fake pasteboard write history remains empty.
- **Assertion strategy**: Level 1/2 — exact notice and zero writes for each input.
- **Mock boundary**: recogniser and pasteboard port.
- **Paired integration test**: `privateNamedPasteboardNoTextConservesContentsAndChangeCount`.
- **Refactor that would break this**: testing only `isEmpty`, trimming ASCII only, or clearing the pasteboard before recognition.

### Case: failure and cancellation are distinct
- **Category**: failure
- **Lane**: unit
- **Spec level**: S3 — provider throws `.recognitionFailed`, `.invalidImage`, `.cancelled`, or `CancellationError`.
- **Input**: each error with the same sentinel state.
- **Expected output**: ordinary errors yield `.failed`; both cancellation forms produce no notice.
- **Observable side effect**: no pasteboard writes; `isRunning` becomes false.
- **Assertion strategy**: Level 1/2 — notice, busy flag and write history after task completion.
- **Mock boundary**: recogniser and pasteboard port.
- **Paired integration test**: `privateNamedPasteboardAndRealServiceRecogniseFixture` (real service/provider error path is already covered by #687a package tests).
- **Refactor that would break this**: showing failure on cancellation, leaving the menu busy, or clearing clipboard on error.

### Case: stale image, close, and late completion conserve state
- **Category**: state
- **Lane**: unit
- **Spec level**: S5 — invariance over A→B, close→late result, and repeated A→B→A identities.
- **Input**: gated recogniser starts A; identity switches to B before gate opens, or model closes; gate returns A text even if cancellation was ignored.
- **Expected output**: cancellation reaches the provider task, no notice or panel and no running task; A's result cannot appear after B or after close. Zoom/pan of unchanged A does not invalidate A.
- **Observable side effect**: fake pasteboard remains untouched.
- **Assertion strategy**: Level 1/2 — record task cancellation at the provider boundary, release gate despite cancellation, await result, assert state and zero writes. Repeat with A→B→A to reject identity reuse, then with zoom/pan alone to assert the result still arrives.
- **Mock boundary**: gated recogniser and fake pasteboard; the gate controls timing only.
- **Paired integration test**: `viewerMenuUsesDecodedSourceAndWindowLifecycle`.
- **Refactor that would break this**: checking URL only, trusting cancellation without a final identity check, or retaining a closed window's completion.

### Case: busy, repeat, panel copy and close transitions

- **Expected output**: busy true only while gated; panel opens only from copied notice, hides notice, edited copy retains panel and briefly confirms; close clears panel; repeat has exactly one new notice.
- **Observable side effect**: pasteboard history `first, second, third` in that order.
- **Assertion strategy**: Level 1/2 — exact state and write sequence after each transition.
- **Mock boundary**: controllable recogniser, clock and fake pasteboard.
- **Paired integration test**: `viewerMenuUsesDecodedSourceAndWindowLifecycle` and `privateNamedPasteboardAndRealServiceRecogniseFixture`.
- **Refactor that would break this**: duplicate callbacks, copying original after edit, dismissing panel on copy, retaining stale notice, or never releasing busy.

- **Observable side effect**: private named boards for each window receive only their corresponding text.

- **Refactor that would break this**: a singleton/global notice, shared in-flight token, or cross-window clipboard result.

**Law**: The overlay remains entirely within the window content bounds with a 20 pt inset, and its editable text area has a fixed 150 pt height as content grows. For every supported content width, panel width is `min(380, contentWidth - 40)` (S4 layout property). One recognition surface exists per window.

## Unit: CommandMenu#RecogniseText and CanvasWindowController#recogniseText

**Law**: Menu enabled state is equivalent to decoded image present ∧ not annotating ∧ not busy ∧ window still open; recognition consumes only the current decoded image's source pixels. This is a state invariant (S5).

### Case: menu availability is a state truth table
- **Category**: guard
- **Lane**: integration (AppKit menu and viewer)
- **Spec level**: S5 — transitions empty→decoded→busy→ready→Annotate→ready→failure→home.
- **Input**: real `CommandMenu` and `CanvasWindowController` with injected decoded image and gated recogniser.
- **Expected output**: disabled, enabled, disabled, enabled, disabled, enabled, disabled, disabled; title en/zh-Hans, no key equivalent in any state.
- **Observable side effect**: no recognition on disabled menu action.
- **Assertion strategy**: Level 3 — validate the actual menu item after each transition and assert model/pasteboard unchanged for disabled states.
- **Mock boundary**: gated recogniser controls busy timing; real menu/window are exercised.
- **Paired integration test**: `viewerMenuUsesDecodedSourceAndWindowLifecycle` with real service/provider.
- **Refactor that would break this**: enabling on home/error/Annotate, leaving busy enabled, or adding an unsupported shortcut.

### Case: viewer menu uses decoded source and window lifecycle
- **Category**: success
- **Lane**: integration (App-hosted)
- **Spec level**: S5 — open A, recognise, change to B before completion; repeat A after B.
- **Input**: full-resolution decoded fixture with text, rendering scale below 1; invoke View › Recognise Text; switch image and close during gated variants. Inject an intent-sensitive recogniser that returns distinct outputs for `.explicit` and `.selection` in the gated variant.
- **Expected output**: full pixel dimensions reach provider through `TextRecognitionService` with `.explicit`; no screen-sized input; A's late result produces no write/notice in B or after close.
- **Observable side effect**: only current result writes one plain string to private named pasteboard.
- **Assertion strategy**: Level 3 — use an output whose OCR differs between source and tiny screen render, inspect decoded input pixel dimensions, real clipboard and window, and assert no stale surface; intent-sensitive result must be the `.explicit` output.
- **Mock boundary**: gated provider variant only for timing; paired non-gated fixture run uses real service/provider.
- **Paired integration test**: `privateNamedPasteboardAndRealServiceRecogniseFixture`.
- **Refactor that would break this**: passing a display thumbnail, wrong intent, stale result or writing to the wrong window board.

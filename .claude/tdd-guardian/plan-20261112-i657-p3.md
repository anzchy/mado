# #657 phase 3 plan

### WI-1: Private invocation status
- Supervisor generates a fresh random ID and destination, publishes one atomic cleanup record, and sends identity only through a private inherited FD.
- Consumer rejects missing, malformed, stale, contradictory and unpublished records.
- RED: `missingMalformedOrStaleCleanupStatusRejectsCounts`, `publicationFailureNeverReportsComplete`, `retryUsesFreshUnpredictableInvocationID`.

### WI-2: Swift and App lane gates
- Swift and App native attempts accept counts only after their own supervisor attests complete cleanup. Pass and completed assertion failure retain 0/1; timeout/cancel and unknown cleanup are 70 without counts.
- RED: `unterminatedDescendantStderrCannotHideIncompleteCleanup`, `incompleteCleanupCannotProduceValidRedReceipt`, `heldAndUnheldLanesPreservePassAndAssertionFailure`.

### WI-3: Hosted and combined gates
- Hosted native attempt uses the same private attestation. Combined results only count attested components.
- RED: hosted cases of `unterminatedDescendantStderrCannotHideIncompleteCleanup` and `heldAndUnheldLanesPreservePassAndAssertionFailure`.

### WI-4: Close same-user status file discovery
- Replace the status file with a private inherited pipe FD. Reject stdio/control FDs as publication destinations.
- RED: `privateStatusDestinationIsNotDiscoverableByChild`, `stdoutCannotBecomePrivateStatusChannel`.

## Risks
- Nested control and flock FDs must be forwarded to the supervisor while the private status FD remains inaccessible to the child workload.
- CI is Linux for Node tests; fixtures must use portable processes.

## Deferred / Out of Scope
- Phase 4 repeat ordering and actual App/hosted CI compatibility audit.

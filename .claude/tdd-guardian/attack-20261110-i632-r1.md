# Specification Attack — tests-20261110-i632.md

## Verdict: GAPS FOUND (1)

## Unit: Coverage export for split runs

### Gap 1: Coverage discovery or export can hang outside the runner deadline
- **Attack**: Unbounded.
- **Passing-but-wrong implementation**:
  ```text
  run both test partitions through the bounded runner
  save their profiles and mark success
  on export, run swift build --show-bin-path without a deadline
  merge and export profiles with unbounded child commands
  publish LCOV when those commands succeed
  ```
- **Why every listed case passes**: Runner timeout cases only hang the Swift test command. Coverage success and invalid-profile cases all terminate; LLVM export-failure case exits 1 immediately. No case stalls discovery, merge, or export.
- **What it would break in production**: A hung Swift discovery or coverage child blocks the local lane; if protected by the heavy lock, it can retain that lock indefinitely despite a bounded test runner.
- **Missing case**: Exercise coverage export with a hostile Swift discovery executable and with hanging merge/export executables. Either avoid Swift rediscovery through captured tested-bundle metadata, or bound every invocation. Timeout must terminate owned workers and leave no successful LCOV.
  - **Level**: S3 — the original unbounded-execution failure at another reachable command boundary.
  - **Lane**: integration.
  - **Assertion**: No Swift discovery launch occurs when saved tested-bundle metadata is used; each hanging coverage child returns a named nonzero timeout within budget plus cleanup, has no live owned helper, and leaves no usable LCOV.

## Attacks defeated by the existing matrix

| Attack | Killed by |

# mado-verify

Run before an implementer handoff, on the final head of the first handoff and again on the final head of every fix round. Claude invokes `/mado-verify`; Codex follows this file. There is no hook: the brief requires this skill (the `## Verify (mado-verify)` section of the brief template), and the delegator checks the record and the issue comment for the final head before audit and before merge with the manual check below.

```sh
node .agents/skills/mado-verify/scripts/evidence.mjs check --head <sha> --issue <n> [--worktree <wt>]
```

It exits 0 and prints `OK head=… issue=… comment=…` only when `.build/mado-verify/<head>.json` exists for that head, the record's issue is `<n>`, every mandatory gate passed, and `commentUrl` is `https://github.com/anzchy/mado/issues/<n>#issuecomment-<digits>` (the canonical repo name; no other repository is accepted). It first prints which case applied: `case=at-head` when the worktree HEAD is `<sha>` (the worktree must then also be clean of tracked changes), or `case=head-moved` when the worktree has moved on, for example after a rebase (the record is still checked; the clean-tree check is not). Anything else (no record, wrong issue, failed or missing gate, missing or foreign comment) exits 1 with the reason. The check does not fetch the comment; the delegator opens it by hand.

### Narrow rebase reuse (#772)

After a rebase, run `node .agents/skills/mado-verify/scripts/reuse-check.mjs <old-base> <new-base> <old-head> <new-head>`. `RERUN <reason>` requires the full gate ladder. `REUSE` permits only the old local `swift` and `lcov` results, and only when `rebase-verify.sh` reports `CODE same`, all main changes are on the explicit `scripts/reuse-allowlist.json`, the tested-input tree hashes match, the Xcode build/Swift version and gate policy hash are unchanged, and the old direct record is green with the same allow-list version. Unknown evidence means `RERUN`.

The checker reads the allow-list, gate policy and reuse policy blobs from **new-base on main** and requires their blobs to match old-base, old-head and new-head. A branch-edited allow-list cannot widen its own reuse permission; a main-side policy change always gives `RERUN`. The old `swift` and `lcov` lanes must each be an executed pass with exit 0, no scope skip or NOT VERIFIED marker. The linked entries copy the old gate entries exactly, including their measured `keyLine`; invented text is refused. Every required new-head lane must be an executed pass, without a scope skip or NOT VERIFIED marker.

For `REUSE`, execute `xcodegen`, `xcodebuild`, `apptests`, `node`, `ledger`, `diffcheck`, and `design` on the new head. Ledger, design and diffcheck always rerun. Create a new issue comment and `.build/mado-verify/<new-head>.json` via `evidence.mjs record` with `base=<new-base>` and `link={oldBase,newBase,oldHead,newHead}`. Mark only the `swift` and `lcov` gate entries `reusedFrom:<old-head>`; other gates must be executed. The record stores both bases/heads, toolchain and tested-input fingerprints, the allow-list version, and per-lane provenance. `evidence.mjs check` recomputes the link and refuses forged or stale evidence. The comment says `reused from <old-head>` for those lanes, never executed. GitHub CI on the new head remains binding. This does not change audit or device-smoke carry-over.

## 0. Define scope

Read the brief, the relevant `docs/feature-ledger.md` acceptance rows, and `git diff --name-status origin/main..HEAD`. The delegator writes `<session-cwd git toplevel>/.build/mado-verify/target-worktree` before dispatch with `scripts/mark-target.mjs`; check its JSON `{worktree, branch, issue, task, handoff}` against the brief (`branch` is the task branch when the delegator passed one), and do not rewrite it as an implementer. The old one-line format is invalid. List applicable layers and write `n/a: <reason>` for each layer that does not apply. Tooling work may have no ledger row. Pin the merge-base and final head SHA.

## 1. Gate ladder

Run gates in a clean worktree at the head: commit first, and never during a rebase, merge or cherry-pick. `owner-gates.sh` refuses (exit 2, summary `refused: …`, no `DONE`) when the worktree has tracked changes, one of those operations is in progress, or HEAD is not the given SHA. Run `git diff --check` yourself first; it is cheap and catches whitespace before the long run. Then run **the current branch's** `.agents/skills/mado-delegator/scripts/owner-gates.sh --role implementer <worktree> <head-sha> <prefix>` (the delegator runs it without `--role`; the default is `delegator`) and read its `*-summary.txt` plus gate logs. Do not invoke a copy from another checkout. Before any lane it writes the machine facts as `load=<1m> mem_free=<percent> pressure=<level>` and refuses (exit 2, `refused: preflight: …` naming the threshold, no lane run) when the machine is over `OWNER_GATES_MAX_LOAD`, under `OWNER_GATES_MIN_MEM_FREE` or over `OWNER_GATES_MAX_PRESSURE` (defaults 6, 25 %, 1; for the owner to set): a loaded machine gives no evidence, not a red lane. Wait and rerun. Facts it cannot read get a `preflight-note:` line and never refuse.

Lanes, in order: `swift`, `lcov`, `xcodegen`, `xcodebuild`, `apptests-retained`, `apptests-hosted`, `apptests`, `node`, `ledger`, `diffcheck`, `design`.

**Node lane selection (#892, owner 2026-11-25).** An implementer run (`owner-gates.sh --role implementer …`, an argument, never the environment: an `OWNER_GATES_ROLE` left in a shell is ignored with a warning and a `role-env-ignored=` summary line) runs the node lane only when the diff from the merge-base touches `scripts/`, `.agents/`, `.github/` or `.claude/` (every node test file lives under them, so a diff that touches a test file selects it); an empty diff runs it too. For a product-only diff the summary says `node=skipped (implementer run; …)`, and the delegator's owner-gates run and GitHub CI cover node. Record that gate as `{"name":"node","exitCode":0,"scopeSkip":"<the summary reason>"}` and copy the summary's `role=` line into the evidence input as top-level `role` (`implementer` or `delegator`; `record` refuses anything else and writes it to the record); a node gate whose `keyLine` or `command` says the lane was skipped (`node=skipped`, a `skipped (…)` reason) without `scopeSkip` is refused, so the skip always reaches this check, while node's own test count in a passing keyLine (`fail 0, skipped 3`) is fine; `evidence.mjs check` refuses the skip unless the record's `role` is `implementer` (the role is copied by hand from the summary; the check cannot bind it to the summary), recomputes the record's base..head diff (`git diff --name-only -z`) and refuses the skip when the diff selects the lane or cannot be listed. Every other lane stays required, and the delegator's run (no `--role`, or `--role delegator`) always runs node. The skip is the owner's prefix rule, not a proof that the diff cannot change a node result: node tests also read product files (a static scan of the node-lane tests and their imports on 2026-11-25 found every top-level product directory named, for example `docs/agents/*.md`, `AppTests/`, `Packages/` and `project.yml`), so the delegator's run is binding. Any other `--role` value is refused (exit 2).

The script never stops at a failure: it runs every selected lane in that order (its own `diffcheck` lane comes late, after `ledger`) so the delegator gets a full summary, and exits 1 when any lane failed. Read the summary in lane order and fix the first failure, then rerun from the start; a later success never excuses an earlier failure. A summary without `DONE` means the run died: no evidence. Its heavy jobs (Swift, `xcodegen`, Xcode build, App tests, browser design check) go through `scripts/heavy-lock.sh`; keep each heavy command separate and foreground. Install design dependencies with `npm ci --ignore-scripts` when that layer applies and `node_modules` is missing.

App tests: when the diff from the merge-base touches `App/`, `AppTests/`, `project.yml` or `Packages/MadoKit/Sources/MadoMacUI/`, the script runs `scripts/heavy-lock.sh xcodebuild build-for-testing -scheme Mado -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO -derivedDataPath .build/dd-ci`, then, with `MADO_APP_FILTER` removed from the environment (by hand: `unset MADO_APP_FILTER`), `scripts/heavy-lock.sh node scripts/tdd/app-lane.mjs '^MadoAppTests\.'`: the full retained MadoAppTests group, unfiltered within it (`apptests-retained=<exit> <run>/<fail>`; exit 0 pass, 1 test failure, 70 environment or incomplete output). The MadoHostedFocusTests group is skipped locally by default (`apptests-hosted=skipped (OWNER_GATES_HOSTED=0; hosted CI binding)`): hosted CI is the binding result for it. `OWNER_GATES_HOSTED=1` runs it locally too. `apptests` is the compatibility line the evidence records: the retained exit, or the hosted exit when the hosted group ran and the retained group passed. Without an App-facing change the script runs a plain `xcodebuild build` and writes `apptests=skip (no App-facing change)`. Plain `xcodebuild test` hangs on the mini ("test runner hung before establishing connection", exit 65); do not use it. Do not replace the retained group with filtered App tests: #702 passed filtered local gates and then failed five App tests of other issues on CI. Record the `apptests` gate in the evidence either way (a skip as `exitCode: 0` with the skip line as `keyLine`; otherwise the `Tests run: N, Failures: F, …` line). Window and layout tests must not depend on the host screen size: CI runs at 1024×768 (#701); size windows explicitly instead of from `NSScreen.main`. Codex sandboxed panes cannot get a key window (`NSApp.isActive=false keyWindow=nil`), so App tests that need one time out there: a Codex implementer records `apptests` as NOT VERIFIED with that log (gate entry `notVerified: "<reason>"`; only `apptests` accepts it, only with exit 70 (environment failure: no result or no key window) and a non-empty reason, and `evidence.mjs check` prints a WARNING line; exit 1, a test failure, always fails whatever the reason). The delegator's `owner-gates.sh` run in the desktop session is then the binding retained result, and hosted CI the binding hosted result. Record exact commands, exit codes and decisive lines. Never weaken a test or add retry/quarantine to turn a gate green.

**Known flakes: there is no flake exception, with one bounded exception for the node lane (#892).** `gate-policy.mjs` rejects every mandatory gate with a non-zero exit, except the `apptests` exit-70 NOT VERIFIED case above and the node flake disposition below; neither `gate-policy.mjs` nor `evidence.mjs` reads [`known-flakes.json`](known-flakes.json).

*The bounded exception: advisory only through a reviewed disposition, never silently green* (Bazel-style FLAKY). When the node lane fails, owner-gates reads the failing tests (`owner-gates-tools.mjs rerun-plan`). If every failing test has a file and none is in the diff, it reruns only those files once, `node --test --test-concurrency=1`, under the heavy lock, and writes `node-attempt1=…`, one `node-failed-test=<file> :: <exact name>` line per test, `node-rerun=<exit> log=<prefix>-node-rerun.log files=…` and `node-verdict=…` to the summary; `<prefix>-node.log` keeps the failed attempt. In the diff means: its file, a file in its directory, a diff test file its name names, or (fail closed, #892 fix1) an empty or unreadable diff, or any changed path under `scripts/`, `.agents/`, `.github/` or `.claude/` puts every failing node test in the diff, because a test's imports, copied fixtures and spawned scripts outside its directory are not proven. An `in-diff=yes` failure, or one without a file, is never rerun (`node-rerun=skipped (…)`). The reviewer still checks that the product files the failing test reads are not in the diff. The run still exits 1 either way. A rerun that fails, times out or passes no test leaves `node-verdict=failed`: fix it. Only `node-verdict=flaky (…)` may be recorded with a disposition, and only after the delegator (or the owner) reviewed it: the `node` gate keeps the attempt-1 exit and adds `attempts` (`[{exitCode, log, tests:[{file,name}]}, {exitCode:0, log, files}]`) and `disposition` `{kind:"flaky", tests (exactly the failing tests), issue (#891 or a successor listed in gate-policy.mjs FLAKE_ISSUES), author (who wrote the record), owner (who fixes the flake), reviewedBy, reviewRef, expires (YYYY-MM-DD, at most 30 days out), failedAttempt (the attempt-1 log)}`. The delegator (or the owner) fills `reviewedBy` with their own name: it must differ from both `author` and `owner` (compared ignoring case, punctuation and a leading `mado-`, so `delegator` and `mado-delegator` are one party). `reviewRef` is where the review can be checked: their comment on anzchy/mado (`…/issues/<n>#issuecomment-<id>`, `…/pull/<n>#issuecomment-<id>`, `#pullrequestreview-<id>` or `#discussion_r<id>`), or a review note under `~/.mado/herdr/delegator/` (never an owner-gates `*-summary.txt`, `*.log` or `*.nul`), a regular file, not a symlink, that `evidence.mjs check` opens and that must contain the reviewer's line `flake-review: head=<full head sha> reviewedBy=<reviewedBy>` (owner-gates never writes it); a URL is printed in the WARNING for the delegator to open, since check works offline. Neither form proves who wrote it: the names and the note are trusted to the reviewer, and the delegator's own owner-gates run stays binding for merge. A reviewer name needs at least one letter or digit; test files are repository-relative paths, and the failing block must account for every failure the run counted (`ℹ fail N`), or there is no rerun. A failing subtest inside a parent test is one such case: node counts the parent too but lists only the child, so it is never rerun and stays red (fails closed). `evidence.mjs check` accepts only that shape, refuses a disposition whose test is in the record's diff, prints `WARNING node FLAKY: …`, and still rejects an unexplained non-zero lane. The comment shows both attempts and says "not a pass".

Outside that exception, the manual list applies. A failing known-flaky test is a failed gate. The list is a diagnosis aid only and is normally empty. Each entry names the file, the exact test name and its anchored rerun pattern, plus `issue`, `owner` and `expires` (a real ISO date at most 30 days out, the `scripts/tdd/app-quarantine.json` shape); `tests/known-flakes.test.mjs` runs in the node lane, so an entry without them or past its expiry fails the lane (#759). When exactly one known-flaky test fails and every other test in the run passed, rerun only that test twice with its exact command, `node --test --test-name-pattern='<pattern>' <file>` (the `pattern` and `file` from the list). If both reruns pass, rerun the whole ladder and record that new run; the failed run is not evidence. Any other failure, two or more failures, or a failed rerun: fix it and rerun the ladder. The gate never retries on its own; its one recorded node rerun above is the only rerun, and it never turns the lane green. A flake not on the list is a failure until the list is changed in a reviewed commit; CI App-test flakes follow `docs/agents/ci-flake-repro.md`.

**Which tooling tests CI runs (#892).** `.agents/skills/mado-delegator/scripts/*.test.mjs` and `.agents/skills/mado-verify/tests/*.test.mjs` are local-only: no GitHub workflow runs them, so green main CI does not cover them; only the node lane of an owner-gates run does. Measured 2026-11-25 on the mini on a green tree (#892 fix1): 186 tests, all passing, in 227 s serially (`--test-concurrency=1`, under the heavy lock). Their time on a GitHub runner was not measured, and these timing-sensitive tests have never run there, so they stay local for now; adding a job needs a runner measurement and the delegator's review of the workflow diff. `pr-body.yml` runs `scripts/agents`, `scripts/tdd`, `scripts/ledger`, `scripts/perf`, `scripts/hooks` and `scripts/device/tests/device.test.cjs`/`platform_split.test.cjs` on Ubuntu for pull requests only (not on pushes to main); `ci.yml` runs `scripts/ci`, `scripts/name-checks`, `scripts/release` and `scripts/device/tests/macos.test.cjs` on macOS.

## 2. Test integrity

Create `.build/mado-verify` first, then run `node .agents/skills/mado-verify/scripts/test-integrity.mjs --base <merge-base> > .build/mado-verify/integrity.json`. Inspect removed or changed `#expect` / `XCTAssert`, new weak assertions, `.disabled(` / `XCTSkip` / `.enabled(if: false)`, retries, removed or increased `.timeLimit`, decreased or removed numeric test `timeout:`, and `exit(0)`. The scan ignores comments and strings; it groups identical findings and lists their locations. Compare before/after test counts, including Swift Testing `@Test` declarations. Read each WI's tdd-guardian RED receipt and SEPARATION verdict; if none exists, say so. Explain **every hit** in the evidence and handoff, including any `SEPARATION-BROKEN`. Hits are review findings, not automatic failures.

## 3. Extra checks by change type

| Change | Run and record |
|---|---|
| Concurrency, cancellation, scanning, caching, watching | Relevant tests repeated with `-test-iterations` and `-run-tests-until-failure` (or a stated loop over the lane), under `scripts/heavy-lock.sh`; record iteration count and failures. No retry. There is no TSan lane in `scripts/` or CI yet; adding one needs its own ticket, so do not claim a TSan run. |
| Bug fix | Regression test RED on old code, GREEN on head; give both SHAs and outputs. If GUI-only, give reproduction steps and a device command. |
| UI state, layout, color | First RED from pinned CSS, then light/dark and other affected appearances. Each state gets AUTO-PASS or NOT VERIFIED. Do not add snapshot-testing dependency. |
| Flaky CI test | Follow `docs/agents/ci-flake-repro.md`, record exact command and run count. Local tooling flakes: step 1 and `known-flakes.json`. |
| Performance-sensitive path | Only report measured signed Release/signpost numbers with machine and build; otherwise NOT VERIFIED. |
| Sandbox authorization, relaunch, menus, window state | Implementer dry-runs scripts or AX selectors; give delegator the signed-app run command and output directory. Delegator performs Device-Smoke and ledger promotion. |

## 4. Issue evidence and record

Fill [`evidence-template.md`](evidence-template.md), preserving its headings and tables. Put structured fields in a JSON input accepted by `scripts/evidence.mjs`; each gate must have a `name`, `command`, and integer `exitCode`. The shared mandatory names live in `scripts/gate-policy.mjs`. `render` checks personal paths and key-like strings, and `post` refuses to call `gh issue comment` if the privacy scan hits. Read the rendered body before posting. `node .../evidence.mjs post <input.json>` posts text to the issue in the brief. Copy the returned comment URL (`https://github.com/anzchy/mado/issues/<issue>#issuecomment-<id>`) into `commentUrl`, then `node .../evidence.mjs record <input.json>` writes `.build/mado-verify/<head>.json` (gitignored). Failed or incomplete gates can be recorded as evidence but never satisfy `evidence.mjs check`. A new commit needs a new comment and record. Put comment URL and covered head SHA in handoff.

For a UI change, screenshots of base and head must use the same state, window size, appearance and scale, and only `TestAssets` content. Scan the crop for private filenames, photos, notifications and other windows. The implementer supplies an exact capture command and output directory. The delegator in the desktop session uploads before/after images via `/browse` into issue comments; `gh` cannot upload comment attachments. The implementer's text and the delegator's images may be separate comments on the same issue. Mark screenshots NOT VERIFIED until uploaded. Do not commit screenshots.

## 5. Repair the recipe

If a command is stale or broken, correct this skill or its owned scripts on the same branch, rerun the affected gate from step 1, and name the correction in handoff. Do not change Device-Smoke, UI-Parity, or ledger acceptance here.

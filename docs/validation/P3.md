4. **先试跑**：`--allow-under-30 --samples 3` 跑一次 `warm-disk`，确认每个样本都有 `GridFirstThumbnails` end 与 `FolderScan` 同 generation 配对（App 扫描 generation 等于快照 generation 只经代码阅读确认）。
5. **三种缓存状态**（各 N ≥ 30；运行目录必须是新的）：
   ```sh
   scripts/perf/measure-p3-08.sh run --app <Picsee.app> --fixture <S2-flat> --tier S2 --cache-state cold-app    --samples 30 --driver '<cmd>' --out <run>-cold
   scripts/perf/measure-p3-08.sh run --app <Picsee.app> --fixture <S2-flat> --tier S2 --cache-state warm-disk   --samples 30 --driver '<cmd>' --out <run>-disk
   scripts/perf/measure-p3-08.sh run --app <Picsee.app> --fixture <S2-flat> --tier S2 --cache-state warm-memory --samples 30 --driver '<cmd>' --out <run>-memory
   ```
   - `cold-app`：每个样本前把 picsee 的缩略图缓存（容器内 `Library/Caches/Picsee/Thumbnails`）**移入**运行目录 `cache-aside/NNN/`（不删除，用完自行清理），再启动新进程。冷应用缓存不等于 OS 文件页缓存已清空。从容器根到 `Thumbnails` 的任一层是符号链接、不是目录、解析后离开容器，或读取出错（只有“不存在”算已冷；EACCES/EPERM 等都算错），脚本即失败，不移动、不把样本标为冷。访问其他 App 容器时 macOS 可能弹出授权，脚本失败而不绕过。
   - `warm-disk`：先做一次不计入的预热打开并退出，之后每个样本重启进程（内存缓存冷、磁盘缓存热）。
   - `warm-memory`：一个进程，预热一次后在同一进程里重复打开 N 次。
6. **资源行**：`scripts/perf/measure-p3-08.sh resources --app … --fixture … --tier S2 --driver '<cmd>' --browse '<滚动/翻页命令>' --rounds 3 --disk-high-water-bytes <配置值> --out <run>-resources`；每轮记 RSS、磁盘缓存大小与最后一个 `ResourceSnapshot`。高水位配置值由记录者给出并注明出处，未给时写 `未知`；是否线性增长由记录者判断。
7. **离线重算**：`scripts/perf/measure-p3-08.sh parse <run dir>` 从 `samples/*.ndjson` 重写 `report.md`；同一进程相邻样本的日志有重叠，同一事件只计一次。

脚本把 `.app/Contents/MacOS/Picsee` 作为自己的子进程启动（不用 `open -n`），只拥有、只向这个子进程发 SIGTERM（不按名字或进程列表认领，不升级信号）；启动前若已有 Picsee 运行即拒绝，启动期间出现的其他 Picsee 不被认领。

### 输出与 `未知`

`report.md` 与 `resources.md` 都有“内容”行：S2 固定写明是很小的合成图、不是照片；其他档位用 `--content` 说明，未给时写 `未知`。`report.md`：每个样本的原始值（open→grid、scan、grid after scan、items、visible/shown/failed）、区间内/外计数、异常；p50/p95（最近秩）/min/max；七个问题与填写模板行。有效样本 < 30 或有任何样本被排除时标为“p95 不可宣称”；预热样本单独标出、不计入。脚本写 `未知` 的项：限制因素（问题 1）、物理上限（问题 3）、缩略图正确性（问题 4 的正确性部分，由自动检查与真机观察另证）、无法从 bundle 证明的 Release 配置与调优设置、读不到的显示 scale 与存储类型。
